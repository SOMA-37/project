# 00. 프로젝트 문서 개요

# 사주 기반 국내 여행지 추천 Agent MVP

## 1. 문서 목적

이 문서는 AI 3주 프로젝트에서 진행하는 **사주 기반 국내 여행지 추천 Agent MVP**의 전체 방향과 문서 구조를 정리하기 위한 개요 문서입니다.

이번 프로젝트는 제한된 기간 안에 Agentic AI 기반 서비스를 기획, 구현, 검증, 발표하는 것을 목표로 합니다.  
따라서 모든 기능을 넓게 구현하기보다는, 사용자가 실제로 입력하고 추천 결과를 확인할 수 있는 MVP를 먼저 완성하는 것을 우선합니다.

이 문서의 목적은 다음과 같습니다.

1. 팀원들이 프로젝트의 핵심 방향을 동일하게 이해하도록 한다.
2. 개발, 기획, 발표 담당자가 참고할 문서 구조를 정리한다.
3. 이번 프로젝트에서 반드시 구현할 MVP 범위를 명확히 한다.
4. Agent Workflow, 기능명세, 데이터 구조, WBS는 각각 별도 문서에서 관리한다.
5. 데모 제출, 프로젝트 제출, 최종 발표 일정에 맞춰 작업 기준을 공유한다.

---

## 2. 프로젝트 한 줄 정의

사용자의 생년월일시와 여행 가능 조건을 입력받아, 사주 기반으로 현재 사용자에게 어울리는 여행 스타일을 분석하고 국내 여행지 3곳을 추천하는 Agent 기반 MVP 서비스입니다.

---

## 3. 서비스 한 줄 정의

생년월일시와 여행 조건만 입력하면, 지금 나에게 어울리는 국내 여행지 3곳을 추천 이유와 함께 보여주는 서비스입니다.

---

## 4. 프로젝트 배경

기존 여행 추천 서비스는 주로 인기 여행지, 거리, 가격, 리뷰, 테마를 중심으로 여행지를 추천합니다.  
하지만 사용자는 선택지가 너무 많아 오히려 어디로 갈지 결정하기 어려운 경우가 많습니다.

또한 사주, MBTI, 타로 같은 자기해석 콘텐츠는 재미 요소는 강하지만, 결과가 실제 행동으로 이어지기 어렵습니다.

이 프로젝트는 이러한 문제를 해결하기 위해, 사주 기반 자기해석 결과를 여행 스타일 키워드로 변환하고, 이를 여행지 데이터와 매칭하여 사용자에게 “지금 나에게 맞는 여행지”를 추천하는 것을 목표로 합니다.

---

## 5. 해결하려는 문제

이번 프로젝트에서 해결하려는 문제는 다음 두 가지입니다.

### 5.1 여행지 선택 피로

사용자는 여행을 가고 싶어도 여행지를 고르는 과정에서 피로를 느낍니다.  
검색 결과는 많지만, 사용자의 현재 기분이나 상태를 반영한 추천은 부족합니다.

이 서비스는 사용자의 여행 조건과 현재 상태 해석을 바탕으로 후보지를 좁혀주어 여행지 선택 피로를 줄이는 것을 목표로 합니다.

### 5.2 자기해석 콘텐츠의 행동 연결 부족

사주와 같은 자기해석 콘텐츠는 흥미롭지만, 결과가 실제 행동으로 이어지지 않는 경우가 많습니다.

예를 들어 “회복이 필요한 시기”라는 결과를 받더라도 사용자는 그래서 무엇을 하면 좋을지 알기 어렵습니다.

이 프로젝트는 사주 분석 결과를 감정 회복, 에너지 충전, 인간관계 환기, 자기 성찰, 액티비티 중심, 문화 탐방과 같은 여행 스타일로 변환하고, 이를 실제 여행지 추천으로 연결합니다.

---

## 6. 핵심 가치

이번 서비스의 핵심 가치는 다음과 같습니다.

1. 여행지 선택 피로를 줄인다.
2. 사주 기반 자기해석을 실제 여행 추천으로 연결한다.
3. 단순 인기 여행지가 아니라 현재 사용자 상태에 맞는 여행지를 추천한다.
4. 추천 이유를 함께 제공하여 결과를 납득할 수 있게 한다.
5. 단순 LLM 호출이 아니라 Agent Workflow 기반 추천 구조를 설계한다.

---

## 7. 대상 사용자

이번 MVP의 주요 대상 사용자는 다음과 같습니다.

- 국내 단기 여행을 가볍게 다니는 20~30대
- 주말 또는 휴일에 당일치기, 1박 2일 여행을 고민하는 사용자
- 사주, MBTI, 타로 등 자기해석 콘텐츠를 가볍게 즐기는 사용자
- 여행지를 직접 검색하고 비교하는 과정에 피로를 느끼는 사용자
- 남들이 많이 가는 곳보다 지금 자신의 상태에 맞는 여행지를 추천받고 싶은 사용자

---

## 8. MVP 목표

이번 프로젝트의 MVP 목표는 다음과 같습니다.

사용자가 생년월일시와 여행 조건을 입력하면, Agent Workflow를 통해 여행 스타일을 분석하고, 여행지 데이터에서 조건에 맞는 Top3 여행지를 추천한 뒤, 추천 이유를 카드 형태로 보여주는 웹 데모를 구현합니다.

MVP에서 중요한 것은 기능을 많이 넣는 것이 아니라, 다음 흐름이 실제로 동작하는 것입니다.

사용자 입력  
→ 사주 기반 상태 분석  
→ 여행 스타일 매핑  
→ 여행지 데이터 검색 및 필터링  
→ 추천 점수 계산  
→ Top3 여행지 선정  
→ 추천 이유 생성  
→ 결과 카드 출력

## 12. 여행 스타일 방향

기존의 단순한 회복형, 활력형, 교류형, 자연몰입형 키워드는 사용자 니즈와 더 직접적으로 연결되도록 구체화합니다.

이번 MVP에서는 다음과 같은 여행 스타일을 기준으로 추천 로직을 설계합니다.

| 여행 스타일 | 사용자 니즈 |
|---|---|
| 감정 회복형 | 지친 감정을 정리하고 안정감을 얻고 싶은 사용자 |
| 에너지 충전형 | 답답함을 풀고 활력을 얻고 싶은 사용자 |
| 인간관계 환기형 | 사람들과의 관계나 분위기를 전환하고 싶은 사용자 |
| 자기 성찰형 | 혼자 생각을 정리하고 내면을 돌아보고 싶은 사용자 |
| 액티비티 중심형 | 몸을 움직이며 스트레스를 풀고 싶은 사용자 |
| 문화 탐방형 | 새로운 취향과 자극을 얻고 싶은 사용자 |

여행 스타일의 구체적인 정의, 태그 매핑 기준, 추천 점수 반영 방식은 `02_function_spec.md`와 `04_data_schema.md`에서 상세히 관리합니다.

## 13. Agent Workflow 방향

이번 프로젝트는 단순히 LLM에게 여행지를 추천받는 구조가 아니라, 여러 단계를 나눈 Agent Workflow 구조를 목표로 합니다.

기본 흐름은 다음과 같습니다.

1. 사용자 입력값 검증
2. 사주 기반 간단 분석
3. 여행 스타일 키워드 매핑
4. 여행지 데이터 검색 및 필터링
5. 추천 점수 계산 및 Top3 선정
6. 추천 이유 생성
7. 결과 카드 출력

코치 피드백을 반영하여, 가능하면 LangChain 또는 LangGraph를 활용해 각 단계를 Chain 또는 Graph 형태로 구성합니다.

다만 프로젝트 기간을 고려하여 우선순위는 다음과 같이 설정합니다.

1. 함수 기반으로 전체 Agent Workflow가 동작하도록 구현
2. 시간이 가능하면 LangChain으로 프롬프트 호출 흐름 정리
3. 추가 여유가 있으면 LangGraph로 분기 구조 표현

Agent별 상세 역할, 입력값, 출력값, 예외 처리는 `03_agent_workflow.md`에서 관리합니다.

## 14. 추천 방식 방향

여행지 추천은 LLM이 임의로 여행지를 생성하는 방식이 아니라, 미리 정의한 여행지 데이터에서 후보를 찾고 점수 기준에 따라 Top3를 선정하는 방식으로 진행합니다.

추천 기준은 다음 요소를 반영합니다.

- 여행 스타일 태그 일치 여부
- 이동 가능 범위 충족 여부
- 여행 기간 적합 여부
- 사용자 선호 태그 일치 여부
- 추천 활동 데이터 존재 여부

LLM은 여행지를 직접 생성하는 역할보다, 선정된 여행지에 대해 사용자에게 보여줄 추천 이유를 자연어로 작성하는 역할에 집중합니다.

상세 점수 기준은 `02_function_spec.md`에서 관리합니다.

| Deployment | 미정 | 데모 상황에 맞춰 로컬 또는 간단 배포 선택 |

기획/문서화 담당자는 개발팀이 구현할 수 있도록 기능 범위와 기준을 명확히 정리합니다.

개발 담당자는 문서에 정의된 MVP 기능을 우선 구현합니다.

발표 담당자는 서비스 정의, Agent Workflow, 데모 시나리오를 중심으로 발표자료를 구성합니다.

문서와 구현 내용이 달라질 경우, 먼저 관련 문서를 수정한 뒤 개발과 발표 자료에 반영합니다.

## 19. 팀 운영 원칙

이번 프로젝트는 기간이 짧기 때문에 다음 원칙으로 진행합니다.

1. P0 기능 완성을 가장 우선한다.

3. 애매한 결정은 문서에 먼저 정리한다.

5. 발표자는 실제 구현된 흐름을 기준으로 발표한다.
6. 일정이 밀릴 경우 즉시 공유하고 기능 범위를 줄인다.
7. 5/10 데모 제출 이후에는 기능 확장보다 안정화와 발표 준비를 우선한다.
8. 5/14 프로젝트 제출 전까지 코드, 문서, 발표자료를 정리한다.

## 20. 최종 완료 기준

이번 프로젝트의 최종 완료 기준은 다음과 같습니다.

- 사용자가 입력 폼에 정보를 입력할 수 있다.
- 입력값을 기반으로 사주 분석 결과가 생성된다.
- 사주 분석 결과가 여행 스타일로 변환된다.
- 여행지 데이터에서 조건에 맞는 후보가 검색된다.
- 추천 점수 기준에 따라 Top3 여행지가 선정된다.
- LLM이 각 여행지에 대한 추천 이유를 생성한다.
- 결과가 웹 화면에 카드 형태로 출력된다.
- 결과 화면에 재미/참고용 면책 문구가 표시된다.
- 5/10 데모 제출이 가능하다.
- 5/14 프로젝트 최종 제출이 가능하다.
- 5/15 최종 발표에서 Agent Workflow와 시연 결과를 설명할 수 있다.

## 21. 한 줄 요약

이번 프로젝트는 사주 기반 자기해석 결과를 여행 스타일로 변환하고, 이를 여행지 데이터와 매칭하여 국내 여행지 Top3를 추천하는 Agent 기반 MVP 서비스입니다.

핵심은 많은 기능을 구현하는 것이 아니라, 데모 제출과 최종 발표 일정 안에서 사용자 입력부터 추천 결과 출력까지의 Agent Workflow가 명확하게 동작하는 모습을 보여주는 것입니다.
