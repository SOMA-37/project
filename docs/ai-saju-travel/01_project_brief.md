# 01. 프로젝트 기획서

# 사주 기반 국내 여행지 추천 Agent MVP

## 1. 프로젝트 개요

### 1.1 프로젝트명

사주 기반 국내 여행지 추천 Agent MVP

### 1.2 프로젝트 한 줄 정의

사용자의 생년월일시와 여행 가능 조건을 입력받아, 사주 기반으로 현재 사용자에게 어울리는 여행 스타일을 분석하고 국내 여행지 3곳을 추천하는 Agent 기반 MVP 서비스입니다.

### 1.3 서비스 한 줄 정의

생년월일시와 여행 조건만 입력하면, 지금 나에게 어울리는 국내 여행지 3곳을 추천 이유와 함께 보여주는 서비스입니다.

### 1.4 프로젝트 성격

이번 프로젝트는 AI 3주 프로젝트 과정에서 진행하는 단기 MVP 프로젝트입니다.

프로젝트의 목표는 완성도 높은 상용 서비스를 만드는 것이 아니라, 짧은 기간 안에 Agentic AI 기반 서비스 흐름을 기획하고, 실제로 동작하는 데모를 구현한 뒤, 최종 발표에서 서비스 구조와 구현 결과를 설명하는 것입니다.

따라서 이번 프로젝트에서는 다음과 같은 기준을 우선합니다.

1. 사용자가 실제로 입력할 수 있는 화면을 만든다.
2. 입력값을 바탕으로 Agent Workflow가 단계적으로 동작한다.
3. 여행지 추천 결과가 화면에 출력된다.
4. 추천 결과가 단순 LLM 생성이 아니라, 사주 분석 → 여행 스타일 매핑 → 여행지 데이터 매칭 → Top3 선정 → 추천 이유 생성의 흐름을 가진다.
5. 5월 10일 데모 제출, 5월 14일 프로젝트 제출, 5월 15일 최종 발표 일정에 맞춰 구현 범위를 관리한다.

## 2. 프로젝트 배경

여행은 많은 사람에게 휴식과 전환의 수단이지만, 막상 여행지를 고르는 과정은 쉽지 않습니다.

특히 국내 단기 여행을 고민하는 사용자는 다음과 같은 상황을 자주 겪습니다.

- 어디든 가고 싶지만 어디로 가야 할지 모르겠다.
- 여행지를 검색하면 정보가 너무 많아 오히려 결정하기 어렵다.
- 인기 여행지나 SNS 추천지는 많지만 지금 내 상태와 맞는지는 모르겠다.
- 여행 목적이 휴식인지, 활력 충전인지, 혼자만의 시간인지 명확하지 않다.
- 주말이나 짧은 휴일에 가볍게 떠나고 싶은데, 여행지를 고르는 과정 자체가 부담스럽다.

한편, 사주, MBTI, 타로 같은 자기해석 콘텐츠는 20~30대 사용자에게 익숙한 콘텐츠입니다. 사용자는 이런 콘텐츠를 통해 자신의 성향이나 현재 상태를 재미있게 해석받는 경험을 즐깁니다.

하지만 대부분의 자기해석 콘텐츠는 결과를 보여주는 데에서 끝나는 경우가 많습니다.

예를 들어, 사용자가 “지금은 회복이 필요한 시기입니다”라는 결과를 받더라도, 그 결과가 실제 행동으로 이어지기는 어렵습니다. 사용자는 결국 “그래서 지금 무엇을 하면 좋을까?”라는 질문을 다시 하게 됩니다.

이번 프로젝트는 이 지점에서 출발합니다.

사주 기반 자기해석 결과를 단순한 운세 콘텐츠로 소비하는 것이 아니라, 사용자의 현재 상태나 필요한 에너지를 여행 스타일로 변환하고, 이를 실제 국내 여행지 추천으로 연결하고자 합니다.

즉, 이 서비스는 단순 여행지 추천 서비스가 아니라, 자기해석 콘텐츠와 행동 추천을 연결하는 실험적 MVP입니다.

## 3. 문제 정의

이번 프로젝트에서 해결하려는 핵심 문제는 다음 두 가지입니다.

## 3.1 여행지 선택 피로

사용자는 여행을 가고 싶어도 여행지를 고르는 과정에서 피로를 느낍니다.

기존 여행 추천 방식은 주로 다음 기준에 의존합니다.

- 인기 여행지
- 거리
- 가격
- 리뷰
- 테마
- SNS 트렌드
- 주변 사람 추천

이러한 기준은 유용하지만, 사용자의 현재 상태나 감정적 니즈를 충분히 반영하지는 못합니다.

예를 들어 같은 강릉 여행이라도 어떤 사용자에게는 감정 회복을 위한 여행일 수 있고, 어떤 사용자에게는 친구들과 활력을 얻기 위한 여행일 수 있습니다. 하지만 일반적인 여행 추천 서비스에서는 이러한 차이를 반영하기 어렵습니다.

이번 프로젝트는 사용자의 현재 상태를 사주 기반으로 가볍게 해석하고, 이를 여행 스타일로 변환하여 여행지 선택 피로를 줄이는 것을 목표로 합니다.

## 3.2 자기해석 콘텐츠의 행동 연결 부족

사주, MBTI, 타로 같은 자기해석 콘텐츠는 사용자의 흥미를 끌기 좋습니다.

하지만 많은 자기해석 콘텐츠는 다음과 같은 한계를 가집니다.

- 결과가 추상적이다.
- 실제 행동으로 이어지기 어렵다.
- 사용자가 결과를 보고 난 뒤 무엇을 해야 할지 알기 어렵다.
- 콘텐츠 소비 후 경험이 끝난다.

이번 프로젝트는 사주 분석 결과를 여행 스타일 키워드로 변환하고, 그 스타일에 맞는 여행지를 추천함으로써 자기해석 결과를 실제 행동으로 연결합니다.

예를 들어 다음과 같은 흐름을 목표로 합니다.

```text
사주 기반 상태 분석
→ 현재 감정적 회복이 필요한 흐름으로 해석
→ 감정 회복형 여행 스타일로 매핑
→ 바다, 숲, 조용한 산책 태그를 가진 여행지 탐색
→ 강릉, 가평, 양양 등 Top3 추천
→ 각 여행지에 대한 추천 이유 생성
````

이처럼 사용자는 단순히 “당신은 회복이 필요합니다”라는 결과를 받는 것이 아니라, “그래서 지금은 이런 여행지가 어울립니다”라는 행동 가능한 추천을 받게 됩니다.

## 4. 프로젝트 목표

이번 프로젝트의 목표는 다음과 같습니다.

## 4.1 사용자 관점 목표

사용자가 생년월일시와 여행 조건을 입력하면, 현재 자신에게 어울리는 여행 스타일과 국내 여행지 3곳을 추천받을 수 있도록 합니다.

사용자는 결과 화면에서 다음 내용을 확인할 수 있어야 합니다.

* 나에게 도출된 여행 스타일
* 해당 스타일이 나온 간단한 이유
* 추천 여행지 Top3
* 각 여행지가 어울리는 이유
* 추천 활동
* 재미와 참고용이라는 안내 문구

## 4.2 서비스 관점 목표

서비스는 사용자의 사주 정보를 기반으로 현재 상태를 가볍게 해석하고, 이 해석 결과를 여행 스타일로 변환합니다.

그 후 미리 정의된 여행지 데이터에서 사용자의 이동 가능 범위, 여행 기간, 여행 스타일에 맞는 후보지를 찾고, 점수 기준에 따라 Top3를 선정합니다.

최종적으로 LLM은 선정된 여행지에 대해 사용자에게 보여줄 추천 이유를 자연어로 생성합니다.

## 4.3 프로젝트 관점 목표

이번 프로젝트는 단순 LLM 호출이 아니라 Agentic AI 구조를 경험하는 것을 목표로 합니다.

따라서 다음 흐름을 프로젝트의 핵심 구조로 잡습니다.

```text
사용자 입력
→ 입력값 검증
→ 사주 기반 상태 분석
→ 여행 스타일 매핑
→ 여행지 데이터 검색 및 필터링
→ 추천 점수 계산
→ Top3 선정
→ 추천 이유 생성
→ 결과 카드 출력
```

이 흐름을 통해 최종 발표에서는 다음을 설명할 수 있어야 합니다.

1. 왜 이 서비스를 기획했는지
2. 사용자의 어떤 문제를 해결하려고 했는지
3. Agent Workflow를 어떻게 설계했는지
4. 사주 분석 결과를 어떻게 여행 스타일로 바꾸었는지
5. 여행지 추천 기준을 어떻게 정했는지
6. 최종 결과가 어떻게 생성되는지

## 5. 대상 사용자

## 5.1 주요 타깃 사용자

이번 MVP의 주요 대상 사용자는 국내 단기 여행을 고민하는 20~30대입니다.

구체적으로는 다음과 같은 사용자를 타깃으로 합니다.

* 주말이나 휴일에 당일치기 또는 1박 2일 여행을 가고 싶은 사용자
* 여행지는 가고 싶지만 어디로 가야 할지 고르기 어려운 사용자
* 사주, MBTI, 타로 등 자기해석 콘텐츠를 가볍게 즐기는 사용자
* 단순 인기 여행지보다 현재 자신의 상태에 맞는 추천을 받고 싶은 사용자
* 추천 결과를 친구에게 공유하거나 이야기 소재로 활용하고 싶은 사용자

## 5.2 대표 페르소나

### 페르소나: 주말 여행을 고민하는 27세 직장인

* 나이: 27세
* 거주지: 서울
* 직업: 직장인
* 여행 성향: 당일치기 또는 1박 2일 국내 여행 선호
* 관심사: 사주, MBTI, 타로, 심리테스트 등 자기해석 콘텐츠
* 문제 상황:

  * 평일에는 업무로 바쁘고 주말에는 쉬고 싶다.
  * 어디든 떠나고 싶지만 여행지를 고르는 과정이 귀찮다.
  * 검색을 해도 정보가 너무 많아 결정하기 어렵다.
  * 남들이 다 가는 곳보다 지금 자신의 상태에 어울리는 곳을 추천받고 싶다.
* 기대하는 경험:

  * 생년월일시와 여행 조건만 입력하면 추천 결과가 바로 나오면 좋겠다.
  * 추천 이유가 있으면 결과를 더 납득할 수 있을 것 같다.
  * 결과가 재미있으면 친구에게 공유하고 싶다.

## 5.3 사용자 니즈

사용자가 원하는 것은 단순히 여행지 목록이 아닙니다.

사용자는 다음과 같은 경험을 기대합니다.

1. 내가 직접 오래 검색하지 않아도 된다.
2. 지금 내 상태에 맞는 추천을 받는다.
3. 추천 이유가 있어 납득할 수 있다.
4. 결과가 가볍고 재미있다.
5. 실제로 떠날 수 있는 국내 여행지를 추천받는다.

## 6. 서비스 컨셉

이번 서비스의 컨셉은 다음과 같습니다.

**“지금 나에게 필요한 여행을 사주 기반으로 가볍게 해석하고, 실제로 갈 수 있는 국내 여행지로 연결해주는 추천 Agent”**

이 서비스는 전문 사주 상담 서비스가 아닙니다.

또한 항공권, 숙소, 예약까지 제공하는 종합 여행 플랫폼도 아닙니다.

이번 MVP의 핵심은 다음 세 가지입니다.

1. 사주 기반 자기해석
2. 여행 스타일 매핑
3. 국내 여행지 Top3 추천

사용자는 복잡한 여행 계획을 세우기 전에, 자신에게 어울리는 여행 방향을 가볍게 확인할 수 있습니다.

서비스는 사용자의 생년월일시를 통해 현재 상태나 필요한 기운을 해석하고, 이를 여행 스타일로 변환합니다. 이후 사용자가 갈 수 있는 범위 안에서 여행지를 추천합니다.

## 7. 핵심 가치

이번 서비스가 제공하는 핵심 가치는 다음과 같습니다.

## 7.1 선택 피로 감소

사용자가 많은 여행지를 직접 검색하고 비교하지 않아도, 조건에 맞는 여행지 3곳을 추천받을 수 있습니다.

## 7.2 자기해석 기반 추천

단순 인기순, 거리순, 리뷰순 추천이 아니라, 사용자의 사주 기반 해석 결과를 여행 스타일로 변환하여 추천합니다.

## 7.3 설명 가능한 추천

여행지 이름만 제공하는 것이 아니라, 왜 이 여행지가 사용자에게 어울리는지 함께 설명합니다.

## 7.4 가벼운 재미와 공유성

사주 기반 추천이라는 요소는 사용자에게 가벼운 재미를 제공합니다. 추천 결과는 친구와 공유하거나 대화 소재로 활용하기 좋습니다.

## 7.5 Agent Workflow 설계 경험

프로젝트 관점에서는 LLM을 단순 응답 생성 도구로만 사용하는 것이 아니라, 여러 단계의 Agent Workflow 안에서 활용하는 경험을 얻을 수 있습니다.

---

## 8. 여행 스타일 방향

기존 기획에서는 여행 스타일을 회복형, 활력형, 교류형, 자연몰입형 등으로 단순하게 정의했습니다.

하지만 추천 로직을 더 명확하게 만들기 위해, 이번 MVP에서는 사용자 니즈와 직접 연결되는 여행 스타일로 구체화합니다.

최종적으로 다음 6개 스타일을 기준으로 추천 흐름을 설계합니다.

| 여행 스타일   | 사용자 니즈                  | 추천 방향                  |
| -------- | ----------------------- | ---------------------- |
| 감정 회복형   | 지친 감정을 정리하고 안정감을 얻고 싶음  | 바다, 숲, 조용한 산책, 힐링      |
| 에너지 충전형  | 답답함을 풀고 활력을 얻고 싶음       | 맛집, 축제, 핫플, 활기 있는 장소   |
| 인간관계 환기형 | 사람들과의 관계나 분위기를 전환하고 싶음  | 카페거리, 시장, 야경, 도시 산책    |
| 자기 성찰형   | 혼자 생각을 정리하고 내면을 돌아보고 싶음 | 사찰, 한옥, 책방, 호수, 조용한 장소 |
| 액티비티 중심형 | 몸을 움직이며 스트레스를 풀고 싶음     | 레저, 트레킹, 서핑, 체험 활동     |
| 문화 탐방형   | 새로운 취향과 자극을 얻고 싶음       | 전시, 역사, 예술, 로컬 문화      |

이 여행 스타일은 사주 분석 결과와 여행지 데이터 사이를 연결하는 중간 기준입니다.

즉, 서비스는 사용자의 사주 분석 결과를 바로 여행지로 연결하지 않습니다. 먼저 여행 스타일로 변환한 뒤, 여행지 데이터의 태그와 매칭합니다.

```text
사주 분석 결과
→ 여행 스타일 키워드
→ 여행지 데이터 태그
→ 추천 후보 선정
→ Top3 추천
```

이 구조를 사용하면 추천 과정이 더 명확해지고, 개발자가 여행지 데이터에 태그를 부여하기 쉬워집니다.

## 9. Agentic AI 적용 방향

이번 프로젝트는 단순히 LLM에게 전체 추천을 맡기는 방식으로 구현하지 않습니다.

예를 들어 다음과 같은 방식은 지양합니다.

```text
사용자 정보 입력
→ LLM에게 "이 사람에게 맞는 여행지 추천해줘" 요청
→ LLM이 여행지와 이유를 한 번에 생성
```

이 방식은 구현은 빠르지만 다음 문제가 있습니다.

1. 추천 기준이 불명확하다.
2. LLM이 실제 데이터에 없는 여행지를 생성할 수 있다.
3. 여행지 추천 결과를 제어하기 어렵다.
4. Agentic AI 프로젝트로 설명하기 어렵다.
5. 개발자가 각 단계의 로직을 개선하기 어렵다.

따라서 이번 프로젝트에서는 다음과 같이 역할을 분리합니다.

| 단계        | 역할                               |
| --------- | -------------------------------- |
| 입력값 검증    | 사용자 입력값을 확인하고 정규화                |
| 사주 분석     | 생년월일시 기반으로 현재 상태나 필요한 기운 분석      |
| 여행 스타일 매핑 | 분석 결과를 6개 여행 스타일 중 하나 또는 두 개로 변환 |
| 여행지 검색    | 여행지 데이터에서 조건에 맞는 후보 탐색           |
| 랭킹        | 점수 기준에 따라 Top3 선정                |
| 응답 생성     | 선정된 여행지에 대해 추천 이유 생성             |

이 구조를 통해 LLM은 모든 판단을 임의로 수행하는 것이 아니라, 각 단계에서 제한된 역할을 수행합니다.

가능하면 LangChain 또는 LangGraph를 활용하여 단계별 흐름을 Chain 또는 Graph 형태로 구성합니다. 다만 일정 제약이 있으므로, 우선은 함수 기반으로 각 단계를 분리하고 전체 흐름을 구현한 뒤, 가능하면 LangChain 또는 LangGraph를 적용합니다.

## 10. 추천 방식

이번 서비스의 여행지 추천은 LLM이 임의로 여행지를 생성하는 방식이 아닙니다.

미리 정의된 여행지 데이터에서 후보를 찾고, 사용자의 조건과 여행 스타일에 맞는 여행지를 점수화하여 Top3를 선정합니다.

추천 방식은 다음 원칙을 따릅니다.

1. 사용자의 이동 가능 범위 안에 있는 여행지를 우선한다.
2. 사용자의 여행 기간에 맞는 여행지를 우선한다.
3. 사주 분석 결과에서 도출된 여행 스타일과 여행지 태그가 잘 맞는 곳을 우선한다.
4. 사용자가 선택한 선호 태그가 있다면 점수에 반영한다.
5. 추천 활동 정보가 충분한 여행지를 우선한다.
6. 최종 추천 이유는 LLM을 통해 자연어로 생성한다.

이 구조의 장점은 다음과 같습니다.

* 추천 기준이 명확하다.
* 개발자가 구현하기 쉽다.
* 발표에서 설명하기 쉽다.
* 여행지 데이터가 늘어나면 추천 품질을 개선할 수 있다.
* LLM이 존재하지 않는 여행지를 만들어내는 문제를 줄일 수 있다.

추천 점수의 구체적인 기준은 `02_function_spec.md`에서 관리합니다.

```text
1. 사용자가 웹 화면에 접속한다.
```

## 14. 기술 구현 방향

MVP 기준 기술 구현 방향은 다음과 같습니다.

| 영역              | 기술                    | 역할                               |

따라서 구현 우선순위는 다음과 같습니다.

1. Streamlit 기반 입력/결과 화면 구현
2. 여행지 데이터 로딩
3. 사주 분석 및 여행 스타일 매핑
4. 여행지 필터링 및 랭킹
5. LLM 추천 이유 생성
6. 전체 흐름 연결
7. 가능하면 LangChain 또는 LangGraph 적용

팀은 이번 프로젝트를 통해 다음 경험을 얻을 수 있습니다.

* 짧은 기간 안에 MVP 범위를 정의하는 경험
* Agent Workflow를 설계하는 경험
* LLM 응답을 서비스 흐름에 연결하는 경험
* 데이터 기반 추천 로직과 LLM 생성 결과를 분리하는 경험
* 데모 제출과 최종 발표 일정에 맞춰 기능 우선순위를 관리하는 경험

---

## 18. 제약사항

이번 MVP는 다음 제약사항을 전제로 합니다.

1. 사주 분석은 전문 상담 수준이 아니라 재미와 참고용으로 제공한다.
2. 출생 시간을 모르는 경우 분석 정확도가 낮을 수 있음을 안내한다.
3. 여행지 데이터는 MVP 범위에서 직접 정리한 JSON 또는 CSV 데이터를 사용한다.
4. 실시간 교통, 숙박, 가격 정보는 반영하지 않는다.
5. 추천 결과는 실제 여행 결정의 참고 자료로만 제공한다.
6. LLM 응답이 실패하거나 형식이 깨질 경우 기본 템플릿 응답으로 대체한다.
7. 프로젝트 기간이 짧기 때문에 P0 기능 구현을 가장 우선한다.

## 20. 최종 요약

이번 프로젝트는 여행지 선택에 피로를 느끼는 사용자를 위해, 사주 기반 자기해석 결과를 여행 스타일로 변환하고 국내 여행지 추천으로 연결하는 Agent 기반 MVP입니다.

핵심은 단순히 LLM에게 여행지를 추천받는 것이 아니라, 다음과 같은 단계적 구조를 갖는 것입니다.

```text
사용자 입력
→ 사주 분석
→ 여행 스타일 매핑
→ 여행지 데이터 검색
→ 추천 점수 계산
→ Top3 선정
→ 추천 이유 생성
→ 결과 출력
```

이번 MVP에서는 기능을 과도하게 확장하기보다, 5월 10일 데모 제출, 5월 14일 프로젝트 제출, 5월 15일 최종 발표 일정 안에서 사용자 입력부터 추천 결과 출력까지의 흐름을 안정적으로 구현하는 것을 목표로 합니다.
