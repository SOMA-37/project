# 06. 데모 시나리오

# 사주 기반 국내 여행지 추천 Agent MVP 데모 시나리오

## 1. 문서 목적

이 문서는 사주 기반 국내 여행지 추천 Agent MVP의 데모 제출과 최종 발표를 준비하기 위한 시나리오 문서입니다.

이번 프로젝트의 주요 일정은 다음과 같습니다.

| 구분 | 날짜 | 목표 |
|---|---|---|
| 데모 제출 | 5월 10일 | 동작 가능한 MVP 데모 제출 |
| 프로젝트 최종 제출 | 5월 14일 | 코드, 문서, 발표자료 제출 |
| 최종 발표 | 5월 15일 | 서비스 설명 및 시연 |

이 문서는 다음 목적을 가집니다.

1. 데모에서 어떤 사용자 흐름을 보여줄지 정리한다.
2. 발표자가 서비스 정의와 Agent Workflow를 설명할 수 있도록 한다.
3. 개발팀이 어떤 시나리오를 기준으로 테스트해야 하는지 명확히 한다.
4. 최종 발표에서 시연이 끊기지 않도록 기본 입력값과 기대 결과를 정리한다.
5. 오류 상황이 발생했을 때 대체 시연 흐름을 준비한다.

---

## 2. 데모 목표

이번 데모의 목표는 많은 기능을 보여주는 것이 아닙니다.

핵심은 다음 흐름이 실제로 동작한다는 것을 보여주는 것입니다.

    사용자 입력
    → 사주 기반 간단 분석
    → 여행 스타일 매핑
    → 여행지 데이터 검색
    → 추천 점수 계산
    → Top3 여행지 선정
    → LLM 추천 이유 생성
    → 결과 카드 출력

데모에서 반드시 보여야 하는 것은 다음 3가지입니다.

1. 사용자가 입력 폼에 값을 넣을 수 있다.
2. Agent Workflow를 거쳐 여행 스타일이 도출된다.
3. 여행지 데이터 기반으로 Top3 추천 결과가 출력된다.

---

## 3. 데모에서 강조할 핵심 메시지

최종 발표에서 강조할 메시지는 다음과 같습니다.

## 3.1 문제 정의

여행을 가고 싶어도 어디로 갈지 고르는 과정 자체가 피로할 수 있습니다.

기존 여행 추천은 인기 여행지, 거리, 리뷰 중심으로 제공되는 경우가 많지만, 사용자의 현재 상태나 감정적 니즈를 반영하기는 어렵습니다.

이 서비스는 사주 기반 자기해석 결과를 여행 스타일로 변환하고, 실제 국내 여행지 추천으로 연결합니다.

## 3.2 서비스 정의

생년월일시와 여행 조건을 입력하면, 지금 나에게 어울리는 국내 여행지 3곳을 추천 이유와 함께 보여주는 서비스입니다.

## 3.3 Agentic AI 적용 지점

이 프로젝트는 LLM에게 한 번에 “여행지 추천해줘”라고 요청하는 구조가 아닙니다.

다음 단계로 역할을 나누었습니다.

1. 입력값 검증
2. 사주 기반 간단 분석
3. 여행 스타일 매핑
4. 여행지 데이터 검색
5. 추천 점수 계산
6. Top3 선정
7. 추천 이유 생성

LLM은 모든 판단을 임의로 수행하지 않고, 사주 분석과 추천 이유 생성 등 자연어 처리와 해석이 필요한 부분에 사용됩니다.

여행지 후보 선정과 점수 계산은 데이터와 코드 로직으로 제어합니다.

## 4. 기본 데모 시나리오

## 4.1 시나리오 이름

감정 회복형 사용자에게 강릉, 가평, 속초 등 회복 중심 여행지를 추천하는 시나리오

## 4.2 사용자 상황

사용자는 최근 피로감이 있고, 주말에 가볍게 1박 2일 여행을 가고 싶어합니다.

어디로 갈지 직접 검색하는 것은 귀찮고, 지금 자신의 상태에 맞는 여행지를 추천받고 싶어합니다.

## 4.3 입력값

| 항목 | 값 |
|---|---|
| 생년월일 | 1999-03-14 |
| 출생 시간 | 신시 |
| 양력/음력 | 양력 |
| 출발 지역 | 서울 |
| 이동 가능 범위 | 3시간 이내 |
| 여행 기간 | 1박2일 |
| 선호 태그 | 바다, 카페, 산책 |

## 4.4 기대 분석 결과

| 항목 | 기대 결과 |
|---|---|
| primary_style | 감정 회복형 |
| secondary_style | 자기 성찰형 |
| style_keywords | 회복, 안정, 정리, 산책 |
| style_reason | 최근에는 지친 감정을 정리하고 안정감을 회복할 수 있는 여행이 어울립니다. |

실제 LLM 결과는 매번 조금 달라질 수 있으므로, 발표에서는 문구가 정확히 같지 않아도 됩니다.

중요한 것은 사주 분석 결과가 여행 스타일로 변환되는 흐름이 보이는 것입니다.

## 4.5 기대 추천 결과

| 순위 | 여행지 | 추천 이유 방향 |
|---:|---|---|
| 1 | 강릉 | 바다 산책과 카페를 통해 감정 회복에 적합 |
| 2 | 가평 | 서울 근교에서 자연과 산책을 즐기기 좋음 |
| 3 | 속초 | 바다와 먹거리로 기분 전환하기 좋음 |

## 4.6 결과 화면에 표시될 내용

결과 화면에는 다음 요소가 표시되어야 합니다.

- 사용자 여행 스타일
- 스타일 도출 이유
- 추천 여행지 Top3
- 각 여행지의 추천 점수
- 각 여행지의 추천 이유
- 추천 활동
- 재미와 참고용 면책 문구

---

## 5. 데모 진행 순서

## 5.1 실제 시연 순서

발표자는 다음 순서로 시연합니다.

1. 서비스 화면에 접속한다.
2. 서비스 제목과 입력 폼을 간단히 보여준다.
3. 생년월일을 입력한다.
4. 출생 시간을 12지시 기준으로 선택한다.
5. 출발 지역을 선택한다.
6. 이동 가능 범위를 선택한다.
7. 여행 기간을 선택한다.
8. 선호 태그를 선택한다.
9. 추천 받기 버튼을 클릭한다.
10. 로딩 또는 분석 중 화면을 보여준다.
11. 결과 화면에서 여행 스타일을 설명한다.
12. 추천 여행지 Top3를 보여준다.
13. 추천 이유와 활동을 설명한다.
14. 화면 하단의 재미/참고용 면책 문구를 보여준다.
15. Agent Workflow가 어떻게 적용되었는지 요약한다.

## 6. 발표용 설명 흐름

## 6.1 도입 설명

발표 시작 시 다음 흐름으로 설명합니다.

    저희 서비스는 여행지를 고르는 과정에서 피로를 느끼는 사용자를 위해 기획했습니다.
    기존 여행 추천이 인기, 거리, 리뷰 중심이었다면,
    저희는 사용자의 사주 기반 자기해석 결과를 여행 스타일로 변환하고,
    그 스타일에 맞는 국내 여행지를 추천하는 MVP를 만들었습니다.

## 6.2 문제 정의 설명

    사용자는 여행을 가고 싶어도 막상 어디로 갈지 고르는 데 피로를 느낍니다.
    또 사주나 MBTI 같은 자기해석 콘텐츠는 재미는 있지만,
    결과가 실제 행동으로 이어지기 어렵다는 한계가 있습니다.
    그래서 저희는 사주 기반 해석 결과를 여행지 추천이라는 행동으로 연결해보고자 했습니다.

## 6.3 서비스 정의 설명

    사용자는 생년월일시와 여행 조건을 입력합니다.
    시스템은 이를 바탕으로 현재 사용자에게 어울리는 여행 스타일을 분석하고,
    미리 정리한 여행지 데이터에서 조건에 맞는 여행지를 찾아
    Top3 추천 결과와 이유를 제공합니다.

## 6.4 Agent Workflow 설명

    단순히 LLM에게 여행지를 추천받는 방식은 사용하지 않았습니다.
    입력값 검증, 사주 분석, 여행 스타일 매핑, 여행지 검색, 랭킹, 추천 이유 생성을
    각각의 Agent 단계로 분리했습니다.

    LLM은 사주 분석과 추천 이유 생성처럼 자연어 해석이 필요한 부분에 사용하고,
    여행지 검색과 Top3 선정은 데이터와 점수 로직으로 처리했습니다.

## 6.5 시연 전 설명

    지금부터는 사용자가 서울에서 1박 2일로 이동 가능한 여행지를 찾는 상황을 가정해보겠습니다.
    선호 태그는 바다, 카페, 산책으로 설정하고,
    추천 결과가 어떻게 나오는지 보여드리겠습니다.

## 7. 화면별 시연 포인트

## 7.1 입력 화면

입력 화면에서 보여줄 포인트는 다음과 같습니다.

| 화면 요소 | 설명 포인트 |
|---|---|
| 생년월일 | 사주 분석의 기본 입력값 |
| 출생 시간 | 한국 만세력 기준 12지시 선택 |
| 출발 지역 | 여행지 이동 시간 필터링 기준 |
| 이동 가능 범위 | 사용자가 갈 수 있는 거리 조건 |
| 여행 기간 | 당일 또는 1박2일 추천 기준 |
| 선호 태그 | 사용자의 직접 취향 반영 |
| 추천 받기 버튼 | Agent Workflow 실행 시작 |

발표 멘트 예시:

    입력은 자연어가 아니라 선택형으로 구성했습니다.
    MVP 단계에서는 선택형 입력이 개발과 추천 기준 관리에 더 적합하다고 판단했습니다.
    특히 출생 시간은 일반 시각 입력이 아니라 만세력 기준 12지시로 선택하도록 구성했습니다.

## 7.2 분석 결과 화면

분석 결과에서 보여줄 포인트는 다음과 같습니다.

| 화면 요소 | 설명 포인트 |
|---|---|
| 여행 스타일 | 사주 분석 결과가 여행 니즈로 변환된 결과 |
| 스타일 이유 | 왜 이 스타일이 나왔는지 설명 |
| 키워드 | 회복, 안정, 정리 등 매핑 근거 |

발표 멘트 예시:

    사주 분석 결과를 바로 여행지로 연결하지 않고,
    먼저 감정 회복형, 에너지 충전형, 자기 성찰형 같은 여행 스타일로 변환했습니다.
    이 단계가 사주 해석과 여행지 데이터 사이를 연결하는 중간 매핑 역할을 합니다.

## 7.3 추천 결과 화면

추천 결과에서 보여줄 포인트는 다음과 같습니다.

| 화면 요소 | 설명 포인트 |
|---|---|
| 추천 순위 | 점수 기준으로 정렬된 Top3 |
| 여행지 이름 | 데이터에 존재하는 여행지만 추천 |
| 추천 점수 | 스타일, 거리, 기간, 선호 태그 기준 |
| 추천 이유 | LLM이 생성한 자연어 설명 |
| 추천 활동 | 데이터에 정의된 활동 기반 |
| 면책 문구 | 재미와 참고용 서비스 안내 |

발표 멘트 예시:

    여행지는 LLM이 임의로 만든 것이 아니라,
    저희가 정리한 여행지 데이터 안에서 필터링과 점수 계산을 통해 선정했습니다.
    LLM은 최종적으로 선정된 여행지에 대해 추천 이유를 자연스럽게 작성하는 역할을 맡았습니다.

## 8. 예외 시나리오

최종 발표에서는 기본 정상 시나리오만 보여줘도 됩니다.

다만 질의응답이나 테스트 상황에 대비해 아래 예외 시나리오를 준비합니다.

---

## 8.1 출생 시간 모름 시나리오

입력값:

| 항목 | 값 |
|---|---|
| 생년월일 | 1999-03-14 |
| 출생 시간 | 모름 |
| 출발 지역 | 서울 |
| 이동 가능 범위 | 3시간 이내 |
| 여행 기간 | 1박2일 |

기대 결과:

- 출생 시간 없이 생년월일 중심으로 분석한다.
- 분석 결과에 “출생 시간이 없어 일부 해석이 단순화될 수 있음”을 안내한다.
- 추천 결과는 정상 출력된다.

발표 또는 Q&A 설명:

    출생 시간을 모르는 사용자도 사용할 수 있도록 했습니다.
    다만 이 경우 사주 분석은 단순화되며,
    결과 화면에서 참고용 안내 문구를 함께 제공합니다.

---

## 8.2 후보 부족 시나리오

입력값:

| 항목 | 값 |
|---|---|
| 출발 지역 | 서울 |
| 이동 가능 범위 | 1시간 이내 |
| 여행 기간 | 당일 |
| 선호 태그 | 액티비티 |

기대 결과:

- 조건에 맞는 후보가 3개 미만일 수 있다.
- 시스템이 조건을 일부 완화한다.
- 조건 완화 안내 문구를 출력한다.
- 가능한 추천 결과를 보여준다.

안내 문구 예시:

    입력하신 조건에 정확히 맞는 여행지가 부족하여 일부 조건을 완화해 추천했습니다.

발표 또는 Q&A 설명:

    후보가 부족한 경우 앱이 멈추지 않도록 조건 완화 로직을 두었습니다.
    예를 들어 이동 범위를 한 단계 넓히거나 선호 태그를 필터가 아닌 점수 기준으로만 반영합니다.

---

## 8.3 LLM 실패 시나리오

상황:

- LLM API 호출 실패
- 응답 형식 오류
- 응답 파싱 실패

기대 결과:

- 앱이 중단되지 않는다.
- 기본 템플릿으로 추천 이유를 출력한다.
- 추천 여행지 Top3는 그대로 보여준다.

fallback 문구 예시:

    강릉은 감정 회복형에 어울리는 태그와 활동을 가진 여행지입니다.
    안목해변 산책, 카페거리 방문을 통해 현재 여행 목적에 맞는 시간을 보낼 수 있습니다.

발표 또는 Q&A 설명:

    LLM 응답이 실패하더라도 추천 결과 자체는 데이터 기반 로직으로 이미 선정되어 있습니다.
    따라서 기본 템플릿을 사용해 결과 화면이 깨지지 않도록 처리했습니다.

## 11. 발표 멘트 초안

## 11.1 시작 멘트

    안녕하세요. 저희는 사주 기반 국내 여행지 추천 Agent MVP를 개발했습니다.
    이 서비스는 여행지를 고르는 과정에서 피로를 느끼는 사용자를 위해,
    생년월일시와 여행 조건을 입력하면 현재 사용자에게 어울리는 여행 스타일을 분석하고,
    국내 여행지 3곳을 추천해주는 서비스입니다.

## 11.2 문제 정의 멘트

    기존 여행 추천은 인기 여행지나 거리, 리뷰 중심으로 제공되는 경우가 많습니다.
    하지만 사용자는 지금 자신이 쉬고 싶은지, 활력을 얻고 싶은지, 혼자 정리할 시간이 필요한지에 따라
    다른 여행지를 원할 수 있습니다.
    그래서 저희는 사주 기반 자기해석 결과를 여행 스타일로 변환하고,
    이를 실제 여행지 추천으로 연결해보고자 했습니다.

## 11.3 Agent Workflow 멘트

    저희는 LLM에게 한 번에 여행지를 추천받는 방식이 아니라,
    입력값 검증, 사주 분석, 여행 스타일 매핑, 여행지 검색, 랭킹, 추천 이유 생성으로 단계를 분리했습니다.
    이를 통해 추천 기준을 명확히 하고,
    LLM이 임의로 여행지를 만들어내는 문제를 줄이고자 했습니다.

## 11.4 추천 로직 멘트

    여행지는 사전에 정리한 데이터에서만 추천합니다.
    각 여행지에는 여행 스타일 태그, 장소 태그, 이동 시간, 여행 기간, 추천 활동이 들어 있습니다.
    사용자의 여행 스타일과 조건을 기준으로 점수를 계산하고,
    상위 3개 여행지를 최종 추천합니다.

## 11.5 시연 연결 멘트

    지금부터 서울에서 1박 2일 여행을 가고 싶은 사용자를 가정해 시연해보겠습니다.
    선호 태그는 바다, 카페, 산책으로 설정하고,
    결과가 어떻게 나오는지 확인해보겠습니다.

## 11.6 마무리 멘트

    이번 MVP는 완성형 여행 플랫폼이라기보다,
    사주 기반 자기해석을 여행 스타일로 변환하고
    데이터 기반 추천으로 연결하는 Agent Workflow를 검증하는 데 초점을 두었습니다.
    향후에는 여행지 데이터를 확장하고, RAG나 지도 API를 연동해 더 정교한 추천 서비스로 발전시킬 수 있습니다.

## 12. 시연 실패 대비 플랜

최종 발표 중 시연이 실패할 가능성에 대비해 아래 자료를 준비합니다.

## 12.1 준비해야 할 백업 자료

| 자료 | 목적 |
|---|---|
| 정상 시연 화면 캡처 | 앱 실행 실패 시 대체 |
| 결과 화면 캡처 | LLM 응답 지연 시 대체 |
| 시연 영상 | 네트워크 문제 대비 |
| 샘플 입력값 표 | 발표 중 입력 실수 방지 |
| 추천 결과 예시 표 | 결과가 예상과 다를 때 설명 보완 |

## 12.2 시연 실패 시 멘트

앱 실행이 실패한 경우:

    현재 시연 환경 문제로 실시간 실행이 어려워,
    사전에 동일한 입력값으로 실행한 결과 화면을 기준으로 설명드리겠습니다.

LLM 응답이 지연되는 경우:

    LLM 응답은 외부 API 상태에 따라 지연될 수 있어 fallback 구조를 준비했습니다.
    추천 여행지 자체는 데이터 기반 점수 계산으로 먼저 선정되며,
    추천 이유 생성이 실패하면 기본 템플릿 문구로 대체됩니다.

추천 결과가 예상과 다른 경우:

    LLM을 사용하는 분석 문구는 실행 시점마다 조금 달라질 수 있습니다.
    다만 여행지 추천은 데이터 기반 점수 계산을 통해 진행되므로,
    전체 추천 흐름은 동일하게 유지됩니다.

7. 결과를 카드 형태로 출력한다.

사주 기반 자기해석 결과를 여행 스타일로 변환하고,  
이를 데이터 기반 여행지 추천으로 연결하는 Agent Workflow를 명확하게 보여주는 것이 목표입니다.
